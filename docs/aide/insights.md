- [ ] framework — `command_hygiene_guard.py`'s rule 1 ("drop the `cd`/`git -C` prefix") grants exactly one exception — `[framework] local_path` from `aide.toml` — so it refuses *every* git operation against any other repository, including directories the session has explicitly declared as additional working directories. That bakes in the assumption that the consumer repo is the only repo an agent ever touches, which fails as soon as one project spans two repos developed together: here the `segfacet` library and a sibling programme repo, where an agent could `git init` the sibling and write files into it (both take a path argument) but could not `git -C <sibling> add`/`commit` them — leaving rescued documents uncommitted for the human to finish by hand. The guard exists to prevent permission-prompt stalls, not as a trust boundary, so the narrow fix is to widen the exception to declared additional working directories, or add an explicit allow-list key (e.g. `[agent] extra_repos`). Note the current shape blocks the honest spelling while leaving `--git-dir`/`--work-tree` open, so it reads as a lint that an agent is rewarded for evading *(2026-07-25)*
