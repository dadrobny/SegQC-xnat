## Scope of this queue

Delivers roadmap **Stage 5 — Synthetic Failure Corpus & Regression Suite (G7)**
in full.

**Milestone delivered:** a reproducible, seeded **synthetic-failure corpus** and
an automated **full-pipeline regression suite** that together prove the Stage 4
heuristic engine detects **every §6 failure mode**. A deterministic generator
perturbs a clean ground-truth (GT) label map with named operators — fragment,
fuse, inject islands, remove level, crop at border, overlap, displace, relabel,
swap, sequence-break — each carrying an *expectation* (the §6 mode it induces and
the labels it should make the engine flag). A small committed fixture set spans
all eight modes plus a clean-GT positive control; the regression suite runs
`segqc run` end-to-end over the corpus and asserts, per case, the expected verdict
**and** which heuristic fired; golden-file JSON snapshots lock output stability and
determinism across repeated runs. On completion the project has an executable,
regenerable safety net that pins current QC behaviour — the exact substrate
Stage 6 (VerSe reference distributions) and Stage 7 (evaluation/calibration) build
their metrics on. This satisfies **G7** (evaluable & regression-testable) and adds
the synthetic-corpus half of **G2**.

**Prioritisation rationale.** The roadmap graph is linear into Stage 5
(`… → 3 → 4 → 5`). Stage 4 is complete (queue-003): the rule engine, its seven
rule families, verdict aggregation, and a shipped default config are all merged,
so the pipeline can already fire ≥1 heuristic per §6 mode on ad-hoc crafted
inputs. Stage 5 is the single next coherent milestone — it turns those ad-hoc
crafted inputs into a **systematic, committed, regenerable corpus** and wraps the
whole pipeline in a regression harness with golden snapshots, closing the gap
between "a rule fires when I hand-build an example" and "every mode is provably
caught by an automated, deterministic suite." It depends only on the completed
Stages 2–4 and is a prerequisite for the Stage 6/7 evaluation work.

## Work items

### Item 036: Synthetic-corpus foundation — clean-GT spine builder & perturbation framework
Establish the deterministic foundation every operator and fixture builds on.
Create a synthetic-corpus module (e.g. `segqc/synth/` or a `tests/`-level
generator package) providing: (a) a **parametric clean-GT spine builder** that
constructs a multi-vertebra instance label map with ordered, plausibly-spaced
vertebra bodies along a smooth spinal curve, configurable level span, voxel
spacing and affine, such that the *real* Stage 4 pipeline judges it `pass` with no
flags — the positive-control base every perturbation starts from; and (b) a
**perturbation framework**: a `Perturbation` abstraction/registry with an
`apply(labelmap, spacing/affine, seed) -> (perturbed_labelmap, expectation)`
contract, where `expectation` records the intended §6 failure mode, the expected
offending labels, and the expected verdict. Perturbations must be seeded and
reproducible (same seed + input ⇒ identical output array).
*Testable:* unit tests assert the clean-GT builder's output, run through the full
`segqc run` pipeline, yields a `pass` verdict with zero flags; an identity/no-op
perturbation returns an array equal to its input and a well-formed expectation;
the same operator with the same seed produces byte-identical arrays across two
invocations; the builder honours anisotropic spacing (physical volumes correct).

### Item 037: Component & shape perturbations — fragment, fuse, inject islands (modes 2, 3)
First operator family, over connected-component / mask topology. Add three seeded
perturbations on the shared framework (036): **fragment** — split one label's body
into two or more comparable disconnected pieces (drives the fragmentation rule);
**fuse** — merge two adjacent labels into a single over-sized label (drives the
bounds / over-segmentation rules); **inject islands** — add one or more tiny rogue
disconnected components to a label (drives the island rule). Each returns an
expectation naming the induced §6 mode and the offending label(s). Targets §6
modes 2 (fused/fragmented) and 3 (islands), i.e. rule families 027/028.
*Testable:* unit tests apply each operator to a clean-GT fixture and assert the
corresponding Stage 4 rule (fragmentation / bounds / island) fires with the
expected offending labels, while the un-perturbed labels stay unflagged; the
operators are seeded/deterministic and preserve label-map dtype and geometry.

### Item 038: Coverage, border & overlap perturbations — remove level, crop at border, force overlap (modes 5, 6, 8)
Second operator family, over label coverage and spatial extent. Add three seeded
perturbations: **remove interior level** — delete a vertebra from the middle of
the span, leaving an anatomical gap (drives the missing-level rule);
**crop at border** — truncate a vertebra against a chosen image-volume face so it
contacts the FOV edge (drives the border-partial rule); **force overlap** — shift
or dilate one label so its mask intersects a neighbour, assigning shared voxels
(drives the overlap rule). Each returns an expectation naming the induced §6 mode
and offending label(s). Targets §6 modes 5 (missing levels), 6 (border-partial),
and 8 (overlap), i.e. rule families 029/031/032.
*Testable:* unit tests apply each operator to a clean-GT fixture and assert the
corresponding Stage 4 rule (coverage / border / overlap) fires with the expected
offending labels; the remove-level operator triggers the missing-level rule but
not a spurious border flag; operators are seeded/deterministic and spacing-aware.

### Item 039: Identity, ordering & alignment perturbations — displace, relabel/swap, sequence-break (modes 1, 4, 7)
Third operator family, over label identity, ordering, and spatial alignment. Add
three seeded perturbations: **displace** — move a vertebra's mask off the fitted
spinal curve while keeping its label (drives the misalignment / spline-offset
rule); **relabel / swap identity** — reassign a vertebra's integer label (or swap
two labels' identities) so the label no longer matches its anatomical position
(drives the mislabel / ordering-inconsistency rule); **sequence-break** — relabel
to produce a non-anatomical, non-monotonic label sequence (e.g. L1 → T12 → L2 →
L5) (drives the sequence-continuity rule). Each returns an expectation naming the
induced §6 mode and offending label(s). Targets §6 modes 1 (misalignment),
4 (semantic mislabel), and 7 (non-continuous sequence), i.e. rule families
030/033.
*Testable:* unit tests apply each operator to a clean-GT fixture and assert the
corresponding Stage 4 rule (misalignment / mislabel / continuity) fires with the
expected offending labels, while a well-aligned in-order GT stays unflagged;
operators are seeded/deterministic.

### Item 040: Committed synthetic fixture corpus spanning all 8 modes + manifest
Use the generators (036–039) to materialise a small, **committed** fixture set
that spans every §6 failure mode plus the clean-GT positive control. For each case
store the scan/label-map inputs the pipeline needs (as compact NIfTI fixtures
and/or a fully reproducible seeded regeneration script) together with a
**manifest** — a versioned data file mapping each case → the §6 failure mode it
represents, the expected offending labels, and the expected QC verdict
(`pass` / `flagged-for-review` / `fail`). Include a documented, one-command
**regeneration path** so the corpus is reproducible and diffs are reviewable.
Keep fixtures deliberately small to bound repository size and test runtime.
*Testable:* a test asserts the manifest enumerates ≥1 case for each of the eight
§6 modes plus a clean-GT case; every referenced fixture exists and loads via the
Stage 0 loader; regenerating from seed reproduces byte-identical fixtures; the
clean-GT case's declared expected verdict is `pass`.

### Item 041: Full-pipeline regression suite over the corpus
Add a **parametrised regression suite** that, for every case in the corpus
manifest (040), runs the complete `segqc run` pipeline end-to-end and asserts both
the **expected verdict** and that the **expected heuristic(s) fired** with the
expected offending labels — the manifest is the single source of expectations, so
adding a corpus case automatically extends coverage. The suite must assert the
clean-GT case passes with no flags (positive control) and that each of the eight
§6 modes is caught by its designated rule (**G7**, **G2**), and must fail loudly
if a case's verdict or fired-rule set drifts from the manifest.
*Testable:* the suite is green — clean GT yields `pass` / no flags; each §6-mode
case yields the manifest's expected verdict with its designated rule among the
fired findings and the expected offending labels; a deliberately mismatched
expectation (spot-check) makes the suite fail, confirming the assertions bite.

### Item 042: Golden-file JSON snapshots & determinism harness *(completes Stage 5)*
Capture **golden-file JSON report snapshots** for each corpus case and add a
determinism harness that re-runs the pipeline and asserts the emitted JSON is
stable — structurally byte-identical across repeated runs and equal to the
committed golden (modulo an explicitly-normalised set of volatile fields such as
timestamps / absolute paths / tool version, which the harness canonicalises before
comparison). Provide a documented, one-command **golden-update path** for
intentional changes so snapshot refreshes are deliberate and reviewable. This
locks output determinism and pins the full Stage 4→5 behaviour, completing Stage 5.
*Testable:* for each corpus case, two successive pipeline runs produce identical
canonicalised JSON, and that JSON equals the committed golden; deleting or
mutating a golden makes the harness fail; the documented update command
regenerates goldens that then compare equal; the golden JSON validates against the
report schema.
