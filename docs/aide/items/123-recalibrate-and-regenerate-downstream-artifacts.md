## Description

Items 119–122 changed what the spinal curve *is* and how a vertebra is measured
against it. Four downstream artifacts were calibrated or built against the
retired interpolating fit, and this item brings all four back into agreement in
one place so the regeneration is auditable rather than scattered across the
queue:

1. **`mislabel`'s `max_offset_mm`.** Still `15.0` — a number tuned in item 033
   against an offset that was structurally always zero. Item 120 shipped the
   held-out estimator and explicitly handed this item the requirement to
   **re-measure the real-GT ceiling under the shipped estimator** before moving
   the threshold, rather than carrying over the `25.0` the 2026-08-27 human gate
   named (that figure came from `scripts/compare_curve_candidates.py`'s
   *interior-only* leave-one-out, a different estimator; under the shipped one it
   would silence the corpus's own mode-1 case, whose displaced label reads
   `18.718604` mm). Recorded in [`insights.md`](../insights.md), 2026-08-28.
2. **`src/segfacet/reference/reference_verse_v1.json`** — the artifact that
   matters most. Built 2026-07-17 from 80 real VerSe19 GT cases under
   `splprep(..., s=0)`, it commits a per-level `spline_offset_mm` distribution
   whose L1 mean is `1.39e-05` mm and T8 mean `5.39e-06` mm: a distribution of
   numerical noise about zero, shipped as if it described real anatomy. Every
   `reference_delta` comparison against `spline_offset_mm` has therefore been
   scoring live measurements against noise.
3. **`src/segfacet/reference/reference_default.json`** — rebuilt by items 119 and
   120 and currently in agreement with a fresh build, but its
   `provenance.config_hash` is a SHA-256 over `config.rules`
   (`reference/artifact.py::config_hash`), which contains `max_offset_mm`. Moving
   the threshold moves the hash, so the artifact must be rebuilt in the same item
   or five committed "rebuild and compare to committed" tests fail by
   construction.
4. **The nine committed goldens** — regenerated by items 119, 120 and 121. They
   carry no config hash, but `MislabelRule`'s misalignment finding is built with
   an f-string ending `f"(threshold {max_offset:.1f} mm)."`
   (`heuristics/mislabel.py`, `_detect_offset_outliers`), so the threshold is
   embedded verbatim in the two cases that fire it: `mode1_displace`
   and `mode6_crop_at_border` each carry `"(threshold 15.0 mm)"` twice, in the
   finding's `reason` and in the report's `message`. Recalibrating therefore moves
   exactly four strings across two files and nothing else — the narrowest possible
   regeneration, and the one this item must prove is that narrow. The same four
   strings are pinned in `tests/test_098_stray_components.py`'s
   `_PRE_098_GOLDEN_VERDICT_AND_FINDINGS` snapshot, which
   `tests/test_102_stage18_validation.py` imports.

**The cohort is reachable, and how it is reached is machine-local.** The VerSe19
training release (80 CT/GT pairs) is mounted on this machine through a gitignored
symlink at the repo-root path `dataset-verse19training`. Two recorded corrections
belong with the rebuild:
[`docs/aide/dataset-verse19.md`](../dataset-verse19.md) documents a nested
`dataset-verse19training/dataset-verse19training/` layout — the zip-extraction
wrapper — which the symlink deliberately skips, and
[`docs/reference-build.md`](../../reference-build.md) restates the same nested
root in its staging recipe. Both are corrected here to name the cohort root as
**machine-local configuration** (`SEGFACET_VERSE_COHORT`, the variable
`aide.toml`'s `[validation]` comment and tests 084/091/118 already use) rather
than a fixed path contract, and to state that discovery is layout-agnostic. The
`.gitignore` entry's trailing slash was already removed on 2026-08-27 (commit
`29c6d1f`); this item pins that with a test rather than re-fixing it.

**The rebuild needs a tool, because the documented recipe is a bash snippet.**
`segfacet.reference.ingest.ingest_cohort` lists **one flat directory
non-recursively** and hardcodes each mask's scan sibling as `<id>_scan.nii.gz`
(item 044's convention). Real VerSe nests masks under
`derivatives/sub-verseNNN/` and names CTs `..._ct.nii.gz`, so an operator must
*stage* the cohort first — today by hand, from a snippet in
`docs/reference-build.md`. A hand-staged rebuild is not auditable and item 125
cannot replay it, so this item ships
**`scripts/rebuild_verse_reference.py`**: an AIDE project tool in the shape of
`scripts/refresh_reference.py` and `scripts/compare_curve_candidates.py` that
resolves the cohort root from configuration, discovers masks by recursive glob,
stages a flat directory of links, drives the existing `build_reference` /
`write_artifact` machinery, and writes a structured summary carrying the real-GT
`spline_offset_mm` distribution and the derived threshold. The summary is what
makes "the recalibrated threshold is justified by the recorded distributions"
mechanically checkable instead of a claim in prose.

**What this item is NOT.**

- It does **not** change the fit (item 119), the offset estimator (item 120), the
  orientation proxy (item 121) or the curvature reduction (item 122). No file
  under `src/segfacet/features/` is touched.
- It does **not** make `mode4_relabel_swap`'s `is_monotonic` false. Stage 28's
  acceptance line expects that and no item in queue-017 owns it — measured on the
  shipped fit it is still `True` on all nine cases. The gap is already recorded in
  [`insights.md`](../insights.md) (item 120, 2026-08-28) and item 125 records the
  criterion against measured fact.
- It does **not** add the observed-range catalogue column (item 124) or replay
  the stage end to end (item 125).
- It does **not** overwrite `reference_default.json` with a real-GT build —
  `docs/reference-build.md`'s bundle-swap prohibition stands, and the two
  artifacts keep their distinct roles.

## Acceptance Criteria

### The rebuild tool

- [ ] **AC1: The tool runs standalone and writes its summary.**
  `scripts/rebuild_verse_reference.py` exposes a callable `main(argv) -> int`;
  invoked with only `--out <dir>` and no reachable cohort it returns `0` and
  writes `<dir>/verse_rebuild_summary.json` containing valid JSON.

- [ ] **AC2: The cohort root is machine-local configuration, never hard-coded.**
  The cohort root resolves from `--verse-cohort` if given, else the
  `SEGFACET_VERSE_COHORT` environment variable, else "not found"; the script
  source contains no literal dataset path (no `dataset-verse19training`, no
  absolute filesystem path).

- [ ] **AC3: An unreachable cohort is a structured skip, not a failure.** With a
  missing root, and separately with an existing root containing no matching
  masks, the summary's `cohort` block records `status: "skipped"` with a
  non-empty `reason`, `main` returns `0`, no traceback is printed, and no file is
  written outside `--out`.

- [ ] **AC4: Mask discovery is layout-agnostic.** Masks are located by a
  recursive glob for `*_seg-vert_msk.nii.gz` beneath the cohort root, so a root
  holding the masks nested one extra directory deep (the zip-extraction wrapper)
  and a root holding them directly yield the same sorted case-id list.

- [ ] **AC5: Staging produces `ingest_cohort`'s flat convention.** For a stand-in
  nested cohort, the staged directory is flat, contains one entry per discovered
  mask under its original filename, and contains a `<subject_id>_scan.nii.gz`
  sibling for every mask whose CT was found — where `<subject_id>` is the mask
  filename with `_seg-vert_msk.nii.gz` stripped, matching `ingest_cohort`'s own
  stem rule.

- [ ] **AC6: Staging never writes inside the cohort root.** After a staged run
  against a stand-in cohort, the set of paths beneath the cohort root and their
  mtimes are unchanged; every file the tool creates lies under `--out` or under a
  caller-supplied staging directory.

- [ ] **AC7: The tool never writes the committed artifact.** No path the tool
  writes lies under `src/segfacet/`; the rebuilt artifact is written to
  `<out>/reference_verse_v1.json` and installing it is a separate, explicit
  operator step (mirroring `refresh_reference.py`, which likewise never touches
  the packaged copy).

- [ ] **AC8: A subject whose CT is missing is recorded, never silently dropped.**
  For a stand-in cohort where one mask has no matching CT, the summary lists that
  subject id under a `subjects_without_scan` array with a reason, and the mask is
  still staged and still ingested.

### The threshold derivation

- [ ] **AC9: The derivation rule is a pure, callable function.** The tool exposes
  `derive_max_offset_mm(distribution) -> float`, taking a loaded
  `ReferenceDistribution`, reading no file, no clock and no environment, and
  returning the same value for the same input on repeated calls.

- [ ] **AC10: The rule is the documented one.** `derive_max_offset_mm` returns
  `max(6.0, S)` where `S` is the smallest positive multiple of `0.5` strictly
  greater than `P`, and `P` is the maximum over levels whose
  `spline_offset_mm.count >= 10` of that level's
  `feature_stats["spline_offset_mm"].percentiles["p99"]`. Levels with fewer than
  10 subjects are excluded. On a synthetic distribution with a known `P` the
  returned value is exactly the rule's value.

- [ ] **AC11: A distribution carrying no qualifying level yields the floor.**
  Given a distribution whose every level has `count < 10`, or which carries no
  `spline_offset_mm` stats at all, `derive_max_offset_mm` returns `6.0` and
  raises nothing.

- [ ] **AC12: The shipped default is the derived value.**
  `heuristics/mislabel.py`'s `_DEFAULT_MAX_OFFSET_MM` equals
  `derive_max_offset_mm(bundled_production_reference())` computed from the
  committed, rebuilt `reference_verse_v1.json`, exactly.

- [ ] **AC13: The config file agrees with the code default.**
  `src/segfacet/default_config.yaml`'s `rules.mislabel.max_offset_mm` equals
  `_DEFAULT_MAX_OFFSET_MM`, and `_DEFAULT_MAX_OFFSET_MM` is no longer `15.0`.

- [ ] **AC14: The threshold sits strictly inside the corpus window.**
  `_DEFAULT_MAX_OFFSET_MM > 5.143859` (the largest `offset_mm` on any committed
  corpus case that must **not** raise a `mislabel` offset finding —
  `mode4_relabel_swap`) and `<= 17.507445` (the smallest `offset_mm` on any case
  that **must** fire — `mode6_crop_at_border`, item 120's AC23).

- [ ] **AC15: The corpus's firing behaviour is unchanged by the recalibration.**
  Through plain `run_qc` over the committed corpus: `mode1_displace` fires
  `mislabel` with union of labels exactly `{22}`; `mode6_crop_at_border` fires
  `mislabel` on `{22}` and `border` on `{22}`; `clean_control` fires nothing with
  verdict `pass`; `mode4_relabel_swap` fires no `mislabel` finding.

- [ ] **AC16: The four calibration margins are recorded where the threshold
  lives.** `heuristics/mislabel.py`'s module docstring states, as numbers: the
  real-GT `P` the rule was derived from and the level attaining it, the chosen
  threshold, `mode4_relabel_swap`'s `5.143859` mm non-firing ceiling,
  `mode6_crop_at_border`'s `17.507445` mm and `mode1_displace`'s `18.718604` mm
  firing readings — and names `reference_verse_v1.json` as the distribution it
  was calibrated against.

- [ ] **AC17: The real-GT false-positive count at the chosen threshold is

## Assumptions  <!-- MANDATORY -->

Clarify mode is `assume` (`aide.toml`), so each ambiguity below was resolved with
the most defensible default and recorded here for audit at the queue boundary.

- **The threshold-selection rule is this item's design decision, and it is
  mechanical.** Queue-017 asks only that "the recalibrated threshold is justified
  by the recorded clean and displaced distributions". A number chosen by
  judgement cannot be re-derived by item 125, so the rule is stated as a function
  of the committed artifact (AC9–AC12): a `p99`-over-levels ceiling, rounded up
  to the next `0.5` mm, floored at `6.0` mm. The `count >= 10` guard exists
  because several VerSe levels (`L6` has three subjects) have a `p99` that is
  effectively one subject's maximum. The `6.0` mm floor exists because a
  threshold at or below `mode4_relabel_swap`'s `5.143859` mm reading would flag a
  case the corpus requires not to fire.
- **The chosen number is not written into this spec, because it is measured —
  but the window it must land in is not theoretical.** Two samples of the real
  cohort were measured while specifying this item (2026-08-29, through
  `extract_feature_record`, i.e. the shipped item-120 estimator and the same code
  path `reference/ingest.py` uses). An 8-subject stride across the 80 masks gave
  114 subject-levels with maximum `8.829` mm, `p99` `6.376`, `p95` `4.549`,
  `p50` `1.594`. A second, denser stride reached per-subject maxima of
  `16.686` mm (`sub-verse043`, 16 levels) and `12.791` mm (`sub-verse061`,
  8 levels). So real clean GT does reach into AC14's window and up toward
  `mode6_crop_at_border`'s `17.507445` mm floor — which is exactly why the rule
  reads a **`p99` over levels** rather than the cohort maximum, and why the
  hand-back condition below is a real possibility rather than a formality. The
  per-level `p99` the rule actually reads is computed over the full 80-case
  build, not over either sample; the builder records the realised `P`, the level
  attaining it and the resulting threshold in the Decisions log and in
  `mislabel.py`'s docstring (AC16).
- **Some real subjects contribute exact zeros, and that is item 120's estimator
  at its boundary, not a build defect.** A subject with exactly four labelled
  levels returns `offset_mm == 0.0` for every level: at `k = min(3, n - 1) = 3`
  with four points the B-spline has as many coefficients as points, so the
  smoothing term has no freedom and the held-out refit interpolates. Measured on
  `sub-verse065` (4 levels, every offset `0.000` mm). Those zeros enter the
  rebuilt distribution's `min` and pull its `mean` down without touching the
  `p99` the rule reads, so the calibration is unaffected; AC18's "real spread"
  bound is stated on the **mean** over levels with `count >= 10`, which pools
  many subjects per level and is not dominated by them. Captured in
  [`insights.md`](../insights.md) as a follow-up for item 120's fallback
  boundary; not fixed here.
- **If the rule's value exceeds `17.507445` mm, the item hands back rather than
  clamping.** Clamping down would knowingly flag real anatomy the artifact says is
  normal; clamping up would silence `mode6_crop_at_border`'s deliberate finding
  (item 120's AC23) and move a merged item's pinned behaviour. Neither is an
  agent's call — it is the deformity envelope the 2026-08-27 human gate exists to
  decide, and re-opening it needs a person. In that case the builder records the
  measurement, leaves `max_offset_mm` at `15.0`, and hands back naming the
  conflict. No new gate row is added pre-emptively: the existing gate is
  **✅ Approved** and the expected path needs no decision, so a `Blocks: 123` row
  would stall an unattended run on a decision that is probably not required.
- **No human gate is raised, and none is resolved here.** The spinal-curve-model
  gate (`progress.md`, `## Human gates`, `Blocks: 119, 120, 121, 123, 125`) is
  ✅ Approved (2026-08-27), so this item is released. Re-measuring the ceiling
  under the shipped estimator and re-applying an already-approved judgement is
  not a new clinical decision; adopting a threshold outside the corpus window
  would be, which is what the hand-back above protects.
- **The rebuild tool is a new script, not an extension of
  `scripts/refresh_reference.py`.** Item 083's wrapper passes `--verse-cohort`
  straight into `build_reference`, whose `ingest_cohort` lists one directory
  non-recursively — so against the real VerSe layout it finds no masks and
  records `verse-build: failed`. Fixing that inside item 083's tool would widen a
  merged item's contract (its summary step names, its exit-code semantics, its
  tests); a dedicated tool that owns staging keeps both blast radii small. The
  gap in `refresh_reference.py` is captured in [`insights.md`](../insights.md).
- **Staging links rather than copies.** The cohort is ~6.6 GB; the tool creates
  symlinks and falls back to copying when the platform refuses them (Windows
  without developer mode), recording which mode it used in the summary. Either
  mode satisfies `ingest_cohort`, which only opens the paths.
- **The staged CT sibling comes from `rawdata/`.** For a mask
  `<id>_seg-vert_msk.nii.gz`, the CT is discovered by recursive glob for
  `<id>_ct.nii.gz` beneath the cohort root and linked as `<id>_scan.nii.gz`,
  which is `ingest_cohort`'s hardcoded sibling name. A subject with no CT is
  recorded (AC8) and still contributes geometry and morphology features, which is
  what the existing artifact does for the levels whose intensity `count` is
  lower than their geometry `count`.
- **`build_date` is caller-supplied and pinned in the summary.**
  `build_reference` never reads `date.today()` (item 082), so the committed
  artifact's `provenance.build_date` is whatever the operator passed. The rebuild
  uses the date it is actually run, recorded in `docs/reference-build.md` (AC29),
  so a re-run of the same command reproduces the same provenance.
- **`config_hash` moves, and that is why `reference_default.json` must be rebuilt
  here.** `reference/artifact.py::config_hash` hashes `config.rules`, which holds
  `max_offset_mm`. Deferring the default artifact's rebuild would leave five
  committed "rebuild and compare to committed" tests red
  (`test_045_reference_artifact.py::test_ac10_regenerating_reproduces_committed_bytes`,
  `test_063_reference_intensity.py`'s two, `test_081_reference_morphology.py`'s
  two), and under this repo's `auto-merge` mode a red suite cannot merge. Items
  119 and 120 resolved the identical tension the same way.
- **The rebuilt VerSe artifact's non-spline statistics may move, and the item
  must measure rather than assume.** The committed artifact was built on
  2026-07-17; items 089, 093, 098, 108, 116 and 119–121 have all touched feature
  extraction or the label convention since. The rebuild is therefore compared
  leaf by leaf against the pre-123 artifact and the footprint recorded in the
  Decisions log; any moved statistic outside `spline_offset_mm` is reported
  rather than absorbed, because
  `tests/test_093_tptbox_label_convention.py::test_ac5_l6_feature_stats_byte_for_byte_identical_to_pre_rename_s`
  pins L6's complete `feature_stats` against a literal snapshot and
  `tests/test_090_reference_derived_defaults.py` derives `bounds` and
  `fragmentation` thresholds from the artifact's percentiles. See
  [Testing Strategy](#testing-strategy) for the reconciliation of both.
- **Item 093's AC5 snapshot is narrowed, not deleted.** Its point — the July
  edit was a **re-key**, not a re-fit — was true then and is a fact about that
  edit, not about the current artifact. After a deliberate re-fit the
  byte-for-byte assertion asserts a state that no longer exists, so it is
  narrowed to the features a re-fit cannot move, with the excluded features named
  and the reason stated in the test. If the measured footprint turns out to be
  `spline_offset_mm` alone, only that key is excluded.
- **`test_098`'s digest fence is updated, not retired.**
  [`docs/aide/golden-decision-table.md`](../golden-decision-table.md) carries a
  human-signed row for `src/segfacet/reference/reference_verse_v1.json` whose
  disposition is **keep**, on the grounds that the artifact is not regenerable in
  CI and the pin is the only thing standing between it and silent corruption.
  That judgement is unchanged by this item — the artifact is still not
  CI-regenerable — so the fence stays and only its literal moves. No cell of that
  table changes (the "asserted by" test id is the same test), so the table is
  **not** in this item's authorised paths.
- **Interface pinned from the shipped code on this branch:**
  `segfacet.reference.build_reference(cohort_dir, *, source, build_date, config=None,
  convention=None, seg_suffix=DEFAULT_SEG_SUFFIX, with_intensity=True,
  with_morphology=True)`; `write_artifact(dist, path)`; `load_artifact(path)`;
  `config_hash(config)`; `bundled_default_config()`;
  `bundled_production_reference()` / `bundled_production_reference_path()`

## Implementation Steps

1. **`scripts/rebuild_verse_reference.py` — the skeleton.** Follow
   `scripts/refresh_reference.py`'s shape: module docstring naming item 123,
   `REPO_ROOT`, an `argparse` parser (`--out`, `--verse-cohort`, `--staging-dir`,
   `--build-date`, `--seg-suffix`, `--max-cases`), `main(argv) -> int`, and a
   testable `run_rebuild(...)` helper returning the summary dict that is also
   written to `<out>/verse_rebuild_summary.json`. Import only `segfacet.*`
   production modules; never import `tests`.

2. **Cohort resolution and discovery (AC2–AC4).** Resolve `--verse-cohort` →
   `os.environ["SEGFACET_VERSE_COHORT"]` → not found. Discover masks with
   `Path(root).rglob("*" + seg_suffix)`, sorted, so the zip wrapper directory is
   irrelevant. Record the resolved root, the mask count and the discovery glob in
   the summary's `cohort` block; an absent root or an empty match list is
   `status: "skipped"` with a reason and exit `0`.

3. **Staging (AC5, AC6, AC8).** Build the flat staging directory under
   `--staging-dir` (default `<out>/staged_verse`): for each mask, link it under
   its own filename; derive `subject_id` by stripping `seg_suffix`; recursively
   glob `<subject_id>_ct.nii.gz` and link it as `<subject_id>_scan.nii.gz`. Try
   `os.symlink` first and fall back to `shutil.copy2` on `OSError`/
   `NotImplementedError`, recording `stage_mode` in the summary. Write nothing
   beneath the cohort root.

4. **Build (AC7, AC19, AC20).** Call `build_reference(staging_dir,
   source="verse-v1", build_date=<arg>, seg_suffix=<arg>)` with the default
   config, then `write_artifact(dist, out / "reference_verse_v1.json")`. Record
   the artifact path, `subject_count`, the level key set and
   `provenance.config_hash` in the summary. Never write under `src/segfacet/`.

   `derive_max_offset_mm(distribution) -> float` implementing the rule exactly as

   fraction, computed from the ingested per-subject values), and the ten
   subject ids with the largest held-out `spline_offset_mm`.

6. **Run it on this machine** against the mounted cohort and read the numbers.
   Install the rebuilt artifact by copying `<out>/reference_verse_v1.json` over
   `src/segfacet/reference/reference_verse_v1.json` — an explicit operator step,

**Adversarial / edge cases.**

  both follow it; `rglob` on a symlinked root is exercised explicitly.

  stripping — recorded, not silently overwritten in the staging directory.

  the build. The four-level case is worth an explicit assertion: measured on real
  GT while specifying this item, a 4-level subject returns `offset_mm == 0.0` for

  values.
- `--out` pointing at a not-yet-existing nested parent — created with parents.
- `SEGFACET_VERSE_COHORT` set to an empty string — treated as unset, not as the
  current directory.
- `derive_max_offset_mm` on a distribution whose `p99` is exactly a multiple of
  `0.5` — the "strictly greater" half of AC10 is what this pins.

## Decisions & Trade-offs

- **`scripts/rebuild_verse_reference.py` was implemented and run against the
  real, 80-subject VerSe19 training cohort mounted at this machine's
  `SEGFACET_VERSE_COHORT` (the `dataset-verse19training` symlink; no nested
  zip-extraction wrapper on this machine — the root discovered directly
  contains `derivatives/` and `rawdata/`, which the tool's recursive glob
  handles with no flag). The run completed cleanly: `cohort.status == "ran"`
  with `mask_count == 80`, no `staging`/`build` step skipped,
  `build.subject_count == 80`, and all 25 canonical levels (`C1`-`C7`,
  `T1`-`T12`, `L1`-`L6`) present. `derive_max_offset_mm`, AC9-AC11's pure
  rule, is implemented exactly as specified and unit-tested independently of
  any cohort.
- **The measured real-GT ceiling `P` is `21.209073949050172` mm, attained at
  level `L5` (`count = 62` subjects, comfortably above the `count >= 10`
  qualifying floor).** Every other level's `p99` stays below `14.25` mm
  (`T10`, the next-highest). The rule's derived threshold is
  `S = 21.5` mm (the smallest multiple of `0.5` mm strictly greater than
  `P`), and `max(6.0, 21.5) = 21.5`.
- **HAND-BACK: `21.5` mm falls outside AC14's approved corpus window
  `(5.143859, 17.507445]`.** Per this item's own Assumptions ("If the rule's
  value exceeds `17.507445` mm, the item hands back rather than clamping"),
  the recalibration is **not applied**. `heuristics/mislabel.py`'s
  `_DEFAULT_MAX_OFFSET_MM` stays `15.0`; `default_config.yaml` is unchanged;
  the committed `reference_verse_v1.json`, `reference_default.json` and the
  nine corpus goldens are **not** touched by this item, and
  `test_098_stray_components.py`'s `_PRE_098_REFERENCE_VERSE_V1_SHA256`
  fence is **not** updated. AC12-AC28 and AC33 therefore do not pass as
  committed on this branch — this is the deliberate, spec-mandated outcome
  of the measurement landing outside the approved window, not an
  implementation defect, and needs a **person** to decide whether to widen
  the 2026-08-27 "Spinal curve model — the deformity envelope" gate before
  any of that work can land. Clamping either direction was rejected for the
  reasons the Assumptions section states: clamping down would knowingly
  flag real, GT-clean anatomy at `L5`; clamping up would silence
  `mode6_crop_at_border`'s deliberate corpus finding.
- **What *is* committed by this item:** the rebuild tool itself
  (`scripts/rebuild_verse_reference.py`, AC1-AC11 and AC17, all
  cohort-independent or exercised against stand-in cohorts and unaffected by
  the hand-back), and the documentation corrections that describe the tool
  and the machine-local cohort-root configuration
  (`docs/aide/dataset-verse19.md`, `docs/reference-build.md`, AC29-AC31 —
  none of which asserts a specific threshold value). `docs/reference-build.md`
  additionally records this run's outcome (cohort size, date, measured `P`,
  derived value, and the hand-back) so a reader can tell an artifact
  generation was attempted and why the threshold did not move — this
  satisfies the spirit of AC32 (a dated, evidenced record of the rebuild)
  without asserting the recalibration completed, since it did not.
- **Why `L5` reads so high is not investigated further here** — diagnosing
  whether this is a genuine severe-scoliosis / transitional-vertebra
  boundary effect in the real cohort, or an artefact of item 120's held-out
  estimator, is exactly the kind of judgement the deformity-envelope gate
  exists to make, and is out of this item's scope regardless of outcome.
  Captured in `insights.md` as a follow-up pointer for whoever revisits the
  gate.

  `test_ac16_default_max_offset_mm_still_15`) were already retired by the
