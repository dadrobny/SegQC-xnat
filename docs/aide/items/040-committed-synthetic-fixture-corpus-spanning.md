## Description

Use the merged Stage 5 generators (items 036–039) to **materialise a small,
committed fixture corpus** that spans every §6 failure mode **plus** the clean-GT
positive control, together with a **versioned manifest** that is the single
source of expectations for the downstream regression suite (item 041) and golden
snapshots (item 042).

Two deliverables:

1. **A packaged corpus generator** — a new module `src/segqc/synth/corpus.py`
   that encodes a **data-driven recipe** (one entry per case: which
   `Perturbation`, its constructor params, its seed, and the base clean-spine
   build parameters), builds each case from `build_clean_spine()` + the operator,
   and both (a) writes compact NIfTI fixtures + the manifest to disk and (b)
   exposes an in-memory API (`build_corpus()`, `load_manifest()`, `write_corpus()`)
   and a **one-command regeneration entry point** (`python -m segqc.synth.corpus`).

2. **The committed corpus artefacts** under `tests/corpus/` — a `manifest.json`
   and the per-case NIfTI fixtures under `tests/corpus/fixtures/` — generated by
   that entry point and checked in, so the corpus is reproducible and its diffs
   are reviewable.

The manifest maps each case → the §6 failure mode it represents, the expected
offending labels, and the expected QC verdict (`pass` / `flagged-for-review` /
`fail`). Critically, because **three of the eight modes are structurally
invisible to the plain `run_qc` / `segqc run` pipeline** (see the "Reconstructed-
record modes" section below and the Assumptions), the manifest carries a
**`detection`** discriminator so each case declares *how* its mode is verified:
either **pipeline-detectable** (`run_qc` on the fixture yields the expected
verdict/findings) or **reconstructed-record** (`run_qc` stays clean; the mode is
provably induced only via a reconstructed feature record fed directly to the
designated rule — exactly the technique items 038/039 used in their own tests).

### The nine canonical cases (one per mode + clean control)

Every case is derived from the **default lumbar clean spine**
(`build_clean_spine()` → labels 20–24 = L1–L5, spacing `(1,1,1)`) by applying one
registered operator with an **explicit** target so the offending labels are
deterministic and match items 037–039's own ACs:

| case_id | mode | operator (params, seed 0) | detection | expected_rule_ids | expected_labels | verdict |
|---|---|---|---|---|---|---|
| `clean_control` | 0 | `identity` | pipeline | (none) | (none) | `pass` |
| `mode1_displace` | 1 | `displace(target_label=22)` | **reconstructed_record** | `mislabel` | `{22}` | `flagged-for-review` |
| `mode2_fragment` | 2 | `fragment(target_label=22)` | pipeline | `fragmentation` | `{22}` | `flagged-for-review` |
| `mode3_inject_islands` | 3 | `inject_islands(target_label=22)` | pipeline | `fragmentation` | `{22}` | `flagged-for-review` |
| `mode4_relabel_swap` | 4 | `relabel_swap(target_label=21, neighbour_label=22)` | **reconstructed_record** | `mislabel` | `{21,22}` | `flagged-for-review` |
| `mode5_remove_level` | 5 | `remove_level(target_label=22)` | pipeline | `coverage` | (none — case-level) | `flagged-for-review` |
| `mode6_crop_at_border` | 6 | `crop_at_border(target_label=22, face="anterior")` | pipeline | `border` | `{22}` | `flagged-for-review` |
| `mode7_sequence_break` | 7 | `sequence_break()` (tail L5=24 → T13=28) | pipeline | `sequence` | `{28}` | `flagged-for-review` |
| `mode8_force_overlap` | 8 | `force_overlap(target_label=20, neighbour_label=21)` | **reconstructed_record** | `overlap` | `{20,21}` | `flagged-for-review` |

Mode 2 has two operator realisations (`fragment` and `fuse`); one case per mode
is required, so `fragment` is the canonical mode-2 case (the recipe is a plain
list, so a `fuse` case can be appended later without a schema change).

### Reconstructed-record modes (the material design fact — see Assumptions)

Items 038 and 039 documented and **locked** (with dedicated "run_qc does not
surface it" ACs) that three operators produce a valid single-integer label map
whose induced failure is *structurally* invisible to the plain pipeline:

- **`force_overlap` (mode 8, item 038):** a single-integer label map cannot store
  a voxel owned by two labels, and `extract_feature_record` builds its overlap
  mask-stack **one-hot** (`np.stack([data == label ...])`), so the target/
  neighbour masks are disjoint by construction. Verified via a reconstructed
  two-channel mask stack fed to `detect_overlaps` + `OverlapRule`.
- **`displace` (mode 1, item 039):** the pipeline refits an **interpolating**
  spline (`splprep(..., s=0)`) through *all* present centroids, so every
  `per_label_offsets[*].offset_mm ≈ 0` and the displaced centroid lands back on
  the curve. Verified via a reconstructed **leave-one-out** offset fed to
  `MislabelRule`.
- **`relabel_swap` (mode 4, item 039):** the pipeline orders centroids by
  ascending integer label before refitting, so the spline parameter is monotonic
  by construction and `non_monotonic_pairs` is always empty. Verified via a
  reconstructed `monotonic_consistency` record built from the centroids in **true
  spatial (axis-0) order** fed to `MislabelRule`.

This item **must represent these three cases faithfully** — it commits their real
label-map fixtures and marks them `detection == "reconstructed_record"` with a
`reconstruction` technique key so item 041 knows to verify them via the
reconstructed-record path rather than expecting `segqc run` to catch them. This
item does **not** attempt to fix the underlying pipeline limitation (that would be
an out-of-scope Stage 4 change).

### Scope boundary — what this item is **not**

- **Not the regression suite (item 041).** This item ships the corpus + manifest +
  reproducibility/loadability tests. Item 041 is the parametrised full-pipeline
  suite that asserts, per case, the run_qc verdict / fired rules (and drives the
  reconstruction for the three reconstructed-record cases). This item's own tests
  assert the **positive control still passes** (queue-mandated) but deliberately
  do not re-assert every pipeline case's rule-firing (that is 041's job).
- **Not the golden JSON snapshots (item 042).**
- **Not new operators, rules, extractors, config, or CLI behaviour.** It consumes
  the merged `build_clean_spine` / the registered operators / `run_qc` /
  `load_case` / `bundled_default_config` **unchanged**; it adds no `Perturbation`,
  `Rule`, or extractor and edits none of `perturbation.py`, `clean_gt.py`,
  `component_shape.py`, `coverage_border_overlap.py`, or
  `identity_ordering_alignment.py`.
- **Not a fix for the reconstructed-record limitation.** It documents and
  represents it; it does not change the pipeline.

## Public interface (the corpus surface item 041 consumes)

New module `src/segqc/synth/corpus.py`. Re-exported from `segqc.synth`
(`__init__.py` gains an additive import + `__all__` entries).

```python
# Locations of the committed corpus (resolved relative to the repo layout).
CORPUS_DIR: Path            # .../tests/corpus
MANIFEST_PATH: Path         # .../tests/corpus/manifest.json
FIXTURES_DIRNAME: str = "fixtures"
MANIFEST_VERSION: int = 1

def build_corpus() -> list["CorpusCase"]:
    """Build every case in memory (clean spine + operator applied), returning
    per-case metadata + the scan/seg Nifti1Image + the operator's Expectation.
    No disk I/O; the single source of the recipe."""

def write_corpus(dest: Path) -> Path:
    """Materialise the corpus under *dest*: write per-case NIfTI fixtures + a
    shared base scan under dest/fixtures/, and dest/manifest.json. Deterministic
    (byte-stable) writes. Returns the manifest path."""

def load_manifest(path: Path = MANIFEST_PATH) -> dict:
    """Parse and return the committed manifest dict (stdlib json)."""

def main(argv: Sequence[str] | None = None) -> int:
    """`python -m segqc.synth.corpus [--out DIR]` — regenerate the committed
    corpus (default --out == CORPUS_DIR). Returns 0 on success."""
```

### Manifest schema (`manifest.json`, versioned)

```json
{
  "manifest_version": 1,
  "generator": "segqc.synth.corpus",
  "cases": [
    {
      "case_id": "mode8_force_overlap",
      "failure_mode": 8,
      "failure_mode_name": "overlapping segments",
      "detection": "reconstructed_record",
      "reconstruction": "overlap_mask_stack",
      "perturbation": "force_overlap",
      "perturbation_params": {"target_label": 20, "neighbour_label": 21},
      "seed": 0,
      "base": {"levels": ["L1","L2","L3","L4","L5"],
               "spacing": [1.0,1.0,1.0], "curve_amplitude_mm": 6.0},
      "scan_fixture": "fixtures/base_scan.nii.gz",
      "seg_fixture": "fixtures/mode8_force_overlap_seg.nii.gz",
      "expected_rule_ids": ["overlap"],
      "expected_labels": [20, 21],
      "expected_verdict": "flagged-for-review",
      "detail": "force_overlap: shifted label 20 ... (see item 038)"
    }
    // ... 8 more cases
  ]
}
```

- `detection` ∈ `{"pipeline", "reconstructed_record"}`. `reconstruction` is a
  non-null technique name **only** for reconstructed-record cases (one of
  `"leave_one_out_offset"` (mode 1), `"monotonic_true_spatial_order"` (mode 4),
  `"overlap_mask_stack"` (mode 8)); it is `null`/absent for pipeline cases.
- `expected_rule_ids` / `expected_labels` are **sorted JSON lists** (verbatim
  from `Expectation.to_dict()`), so they diff cleanly and JSON round-trips.
- `perturbation` + `perturbation_params` + `seed` + `base` **fully determine** the
  fixture — this is the "fully reproducible seeded regeneration" contract.
- Fixture paths are **relative to the manifest's directory** so the corpus is
  relocatable; all cases share one base scan (`fixtures/base_scan.nii.gz`) since
  every canonical case derives from the same default clean spine (perturbations
  preserve shape/affine).

## Acceptance Criteria

_One test per criterion. "The corpus" means `load_manifest()` + the committed
fixtures under `CORPUS_DIR`. "Loaded seg/scan of a case" means the arrays/affine
returned by `segqc.io.load_case(scan_path, seg_path)` for that case's resolved
fixture paths._

### A. Manifest structure & completeness

- [ ] **AC1: The manifest loads and is versioned.** `load_manifest()` returns a
      `dict` with `manifest_version == MANIFEST_VERSION` (`== 1`) and a non-empty
      `cases` list; the committed `manifest.json` parses via `json.loads` and the
      whole dict round-trips through `json.dumps`/`json.loads` unchanged.

- [ ] **AC2: Every §6 mode plus the clean control is represented.** The multiset
      of `case["failure_mode"]` over `cases` contains **≥1** entry for **each** of
      `{0, 1, 2, 3, 4, 5, 6, 7, 8}` (0 == clean control).

- [ ] **AC3: Case ids are unique and filesystem-safe.** All `case_id` values are
      distinct, non-empty, and match `^[a-z0-9_]+$`.

- [ ] **AC4: Each case carries the full schema with correct types.** Every case
      dict has the keys `case_id` (str), `failure_mode` (int), `failure_mode_name`
      (str), `detection` (str), `perturbation` (str), `perturbation_params`
      (dict), `seed` (int), `base` (dict), `scan_fixture` (str), `seg_fixture`
      (str), `expected_rule_ids` (list), `expected_labels` (list),
      `expected_verdict` (str), and `detail` (str).

- [ ] **AC5: `failure_mode_name` matches the shared taxonomy.** For every case,
      `case["failure_mode_name"] == FAILURE_MODE_NAMES[case["failure_mode"]]`.

- [ ] **AC6: `expected_verdict` is a valid Severity label.** For every case,
      `case["expected_verdict"]` is one of `{"pass", "flagged-for-review",
      "fail"}` (the `Severity.label` values, item 034).

### B. Detection classification (the reconstructed-record decision)

- [ ] **AC7: `detection` is one of the two kinds.** For every case,
      `case["detection"]` is in `{"pipeline", "reconstructed_record"}`.

- [ ] **AC8: Modes 1, 4 and 8 are classified reconstructed-record; the rest are
      pipeline.** Every case with `failure_mode in {1, 4, 8}` has
      `detection == "reconstructed_record"` and a `reconstruction` value in
      `{"leave_one_out_offset", "monotonic_true_spatial_order",
      "overlap_mask_stack"}`; every case with `failure_mode in {0, 2, 3, 5, 6, 7}`
      has `detection == "pipeline"` and no non-null `reconstruction`.

- [ ] **AC9: Reconstructed-record fixtures faithfully hide their mode from plain
      `run_qc`.** For each `detection == "reconstructed_record"` case, running the
      **loaded** seg through `run_qc(seg_img, bundled_default_config())` emits
      **no** finding whose `rule_id` is in that case's `expected_rule_ids` (i.e.
      the committed fixture genuinely exhibits the documented limitation, so item
      041 must use the reconstruction path).

### C. Fixtures load via the Stage 0 loader

- [ ] **AC10: Every referenced fixture file exists.** For every case, the
      `scan_fixture` and `seg_fixture` paths resolved under the manifest's
      directory exist on disk.

- [ ] **AC11: Every case loads via `load_case` with a non-empty label map.** For
      every case, `load_case(scan_path, seg_path)` returns a `Case` without
      raising, its `scan.data.shape == seg.data.shape`, and its
      `label_inventory` is non-empty.

- [ ] **AC12: The clean-control fixture is the default clean spine.** The
      `clean_control` case's loaded seg `label_inventory` keys are exactly
      `{20, 21, 22, 23, 24}`, each with voxel count equal to
      `build_clean_spine().voxel_counts` for that label.

### D. Positive control & reproducibility

- [ ] **AC13: The clean-control case declares a `pass` verdict (queue-mandated).**
      The manifest case with `failure_mode == 0` has `expected_verdict == "pass"`,
      `expected_rule_ids == []`, `expected_labels == []`, and
      `detection == "pipeline"`.

- [ ] **AC14: The committed clean-control fixture actually passes the real
      pipeline.** `run_qc(<loaded clean_control seg>, bundled_default_config())`
      returns a `CaseResult` with `findings == ()` **and**
      `verdict.overall == Severity.PASS`.

- [ ] **AC15: Regeneration reproduces every fixture's content.** Calling
      `write_corpus(tmp)` into a fresh temporary directory yields, for every case,
      a seg and scan whose loaded arrays and affines are `np.array_equal` to the
      committed fixtures (loaded via `load_case`).

- [ ] **AC16: Regeneration is byte-identical (deterministic writes).** Two
      successive `write_corpus` calls into two fresh temp dirs produce
      byte-for-byte identical fixture files and byte-identical `manifest.json`;
      and each regenerated file is byte-for-byte identical to its committed
      counterpart under `CORPUS_DIR`.

- [ ] **AC17: Manifest expectations equal the operators' `Expectation` (single
      source of truth).** For every non-clean case, rebuilding it
      (`get_perturbation(case["perturbation"])(**case["perturbation_params"])
      .apply(<base clean seg>, case["seed"]).expectation.to_dict()`) yields
      `failure_mode`, `expected_rule_ids`, `expected_labels`, and
      `expected_verdict` equal to the manifest case's corresponding fields.

- [ ] **AC18: The one-command regeneration entry point runs.**
      `segqc.synth.corpus.main(["--out", <tmp>])` returns `0` and writes a
      `manifest.json` that `load_manifest(<tmp>/manifest.json)` parses to a dict
      with the same set of `case_id`s as the committed manifest.

## Assumptions  <!-- MANDATORY: what was assumed when the queued one-liner was ambiguous -->

- **THE MATERIAL DECISION — three modes (1, 4, 8) are `reconstructed_record`, not
  `pipeline`, and the manifest schema encodes both kinds via a `detection`
  discriminator.** The queue's literal wording ("every referenced fixture … loads
  via the Stage 0 loader … regenerating from seed reproduces …") assumes every
  case is a `segqc run`-detectable fixture, but items 038 (`force_overlap`) and
  039 (`displace`, `relabel_swap`) proved — with dedicated locking ACs — that
  those three modes are **structurally invisible** to the one-hot / interpolating-
  spline / ascending-label-refit pipeline. Faithfully representing this (rather
  than papering over it or attempting an out-of-scope pipeline fix) is the crux of
  this item. Each case therefore declares `detection ∈ {"pipeline",
  "reconstructed_record"}`; the three reconstructed cases additionally carry a
  `reconstruction` technique key (`"leave_one_out_offset"` / 
  `"monotonic_true_spatial_order"` / `"overlap_mask_stack"`) naming exactly the
  reconstruction items 038/039 used in their tests, so item 041 verifies them via
  a reconstructed feature record fed to the designated rule. The reconstructed
  cases' `expected_verdict` records the **conceptual** outcome
  (`flagged-for-review`) that the reconstruction demonstrates — **not** what plain
  `run_qc` produces (`pass`) — so item 041 must branch on `detection` and must not
  assert `run_qc(...).verdict == expected_verdict` for them. The validator should
  surface this at the queue boundary.

- **The corpus generator CODE lives in `src/segqc/synth/corpus.py`
  (`source_dir`); the committed corpus DATA lives under `tests/corpus/`.** The
  generator is importable, packaged tooling (consistent with item 036's decision
  to place the whole `synth` framework in `source_dir` for uniform importability,
  and part of G7). The committed NIfTI + manifest are **test assets** consumed by
  items 041/042, so they belong under `tests_dir` (keeping the shipped XNAT
  container lean and giving item 042's golden snapshots a natural home at
  `tests/corpus/golden/`), not in the deployed package. Because they are
  **generated data** (not hand-written tests), materialising them under
  `tests/corpus/` is within this item's builder delivery even though the path is
  under `tests_dir`; the *test module* `tests/test_040_corpus.py` remains the
  test-writer's. `CORPUS_DIR` is resolved from the repo layout (e.g.
  `Path(__file__).resolve().parents[N] / "tests" / "corpus"`); item 041 locates
  the corpus via the same `segqc.synth.corpus` constants. If a reviewer prefers
  package-data placement under `src/segqc/synth/corpus_data/`, the move is
  mechanical.

- **Fixtures are compressed `.nii.gz` and are byte-reproducible.** Verified with
  the installed **nibabel 5.3.3**, which writes gzip via `DeterministicGzipFile`
  (mtime=0): `nib.save` of the default clean spine's mostly-zero label map yields
  a ~1–2 KB file and two successive saves are byte-for-byte identical (measured).
  So `.nii.gz` satisfies both "deliberately small" (~9 tiny files, tens of KB
  total) and the queue's "byte-identical" regeneration (AC16) simultaneously. If a
  future environment ships a non-deterministic nibabel, the writer must pin the
  gzip mtime explicitly; AC15 (loaded-content equality) is the version-robust
  backstop.

- **All nine canonical cases share one base scan.** Every case derives from the
  default `build_clean_spine()` (labels 20–24, spacing `(1,1,1)`,
  `curve_amplitude_mm=6.0`) and the operators preserve shape/affine, so the base
  clean-spine `scan_img` is a valid scan for every case. The writer commits one
  shared `fixtures/base_scan.nii.gz` (each case's `scan_fixture` points at it) and
  a distinct `<case_id>_seg.nii.gz` per case. This bounds repo size and keeps
  `load_case` (which validates scan↔seg shape/affine compatibility) satisfied for
  every case.

- **Cases use explicit operator targets so offending labels are deterministic.**
  The recipe pins `target_label` (and `neighbour_label` where relevant) for every
  perturbed case (see the table), so `expected_labels` are fixed and match items
  037–039's own explicit-target ACs — no reliance on seed-dependent target
  selection. `seed=0` is recorded for interface compliance and future stochastic
  operators, but the canonical cases are deterministic given their explicit
  targets.

- **The manifest is the single source of truth; `expected_*` come from
  `Expectation.to_dict()`.** The generator builds each case by calling the
  registered operator and copies `failure_mode` / `expected_rule_ids` /
  `expected_labels` / `expected_verdict` / `detail` straight from the returned
  `Expectation`, so the manifest can never drift from operator behaviour (AC17).
  `remove_level`'s case is case-level (`expected_labels == []`; the removed level
  name lives in `detail`), consistent with item 038.

- **One case per mode is the minimal committed set (nine cases total).** The queue
  requires "≥1 case for each" mode + a clean control; the recipe is a plain list,
  so additional cases (e.g. a `fuse` mode-2 case, an anisotropic-spacing variant)
  can be appended later without a schema change. Mode 2's canonical case is
  `fragment`.

- **Pinned upstream interfaces (hand back if reality diverged):**
  `build_clean_spine(*, levels, spacing, convention, curve_amplitude_mm) ->
  CleanSpine` with `.scan_img` / `.seg_img` / `.labels` / `.voxel_counts`; the
  registry `get_perturbation(name)` → operator class whose
  `apply(labelmap, seed) -> PerturbationResult(labelmap, expectation)` and
  `Expectation.to_dict()` shape (item 036); the registered operator names
  `identity` / `fragment` / `inject_islands` / `remove_level` / `crop_at_border` /
  `sequence_break` / `displace` / `relabel_swap` / `force_overlap`;
  `segqc.io.load_case(scan_path, seg_path) -> Case` with `.seg` / `.scan` /
  `.label_inventory`; `run_qc(seg_img, config) -> (CaseResult, dict)` with
  `CaseResult.findings` / `.verdict.overall` (`Severity`);
  `segqc.config.bundled_default_config`; `segqc.verdict.Severity.PASS`;
  `FAILURE_MODE_NAMES` (item 036). If any diverged, the builder/validator hands
  back.

## Implementation Steps

Intended code path: new `src/segqc/synth/corpus.py` + an additive re-export in
`src/segqc/synth/__init__.py`, and the committed data under `tests/corpus/`. No
edits to existing operator/rule/extractor/config/CLI modules.

1. **Create `src/segqc/synth/corpus.py`** importing `json`, `argparse`,
   `pathlib`, `numpy`, `nibabel`, `dataclasses`; `build_clean_spine` /
   `CleanSpine` from `segqc.synth.clean_gt`; `get_perturbation` /
   `FAILURE_MODE_NAMES` from `segqc.synth.perturbation`; and the operator modules
   (import them, or `import segqc.synth`, so every operator is registered before
   `get_perturbation` is used). Import from submodules (not the `segqc.synth`
   package) to avoid a circular import if `__init__` re-exports `corpus`.

2. **Define the recipe** — a module-level list of case specs (one dataclass/dict
   per row of the table): `case_id`, `failure_mode`, `detection`,
   `reconstruction` (or `None`), `perturbation` name, `perturbation_params`,
   `seed`, and `base` build params. Keep it a plain declarative list.

3. **`build_corpus() -> list[CorpusCase]`:** for each recipe entry, build the base
   `build_clean_spine(**base)`; instantiate `get_perturbation(name)(**params)`;
   `apply(base.seg_img, seed)` → `(seg_img, expectation)`; assemble a `CorpusCase`
   carrying the metadata, the `scan_img` (the base scan), `seg_img`, and
   `expectation`. The `clean_control` case uses `identity`.

4. **`write_corpus(dest) -> Path`:** create `dest/fixtures/`; write the shared
   `base_scan.nii.gz` once (all cases share one base geometry — assert the base
   scans are array-equal across cases before deduping, else write per-case scans);
   write each `<case_id>_seg.nii.gz`; build the manifest dict
   (`manifest_version`, `generator`, `cases`) where each case's `expected_*` /
   `failure_mode_name` / `detail` come from `expectation.to_dict()` and the
   fixture paths are **relative** to `dest`; write `dest/manifest.json` with
   `json.dump(..., indent=2, sort_keys` on inner lists already sorted by
   `to_dict`, ensure a trailing newline for clean diffs). Writes must be
   deterministic (nibabel's deterministic gzip; stable JSON key order).

5. **`load_manifest(path=MANIFEST_PATH) -> dict`:** `json.loads(path.read_text())`.

6. **Module constants:** `CORPUS_DIR` (repo `tests/corpus`), `MANIFEST_PATH`,
   `MANIFEST_VERSION = 1`, resolved from `Path(__file__)`.

7. **`main(argv=None) -> int`:** `argparse` with `--out` defaulting to
   `CORPUS_DIR`; call `write_corpus(Path(out))`; return 0. Add
   `if __name__ == "__main__": raise SystemExit(main())`.

8. **Regenerate + commit the data:** run
   `.venv/Scripts/python -m segqc.synth.corpus` to materialise
   `tests/corpus/manifest.json` + `tests/corpus/fixtures/*.nii.gz`, and commit
   them alongside the module.

9. **Re-export** `build_corpus`, `write_corpus`, `load_manifest`, `CORPUS_DIR`,
   `MANIFEST_PATH`, `MANIFEST_VERSION` from `src/segqc/synth/__init__.py` (additive
   import line + `__all__` entries).

10. **Do not** edit any operator/rule/extractor/config/CLI module, and do not
    change the pipeline to surface the reconstructed-record modes.
